Update from GitHub

The vessel takes its update as a command on the telemetry link, the same way it takes E-stop, and acks the result here. Other nodes poll this server every 30 s from their own update.py; the dashboard updates itself in-process. Every one of them fast-forwards only — a checkout with uncommitted changes refuses the update rather than discarding it. Updating ligmax-pi restarts its nodes, which drops propulsion power for the length of the restart.

Navigation

The course

One waypoint per line. Two numbers are read as latitude then longitude; three or more and the first is taken as the point's label, which is how 1.1 63.43112 10.39640 works. A role word anywhere on the line sets that row's role. Everything is shown back as a table below before anything is sent. Ctrl+Enter reads the box.

Nothing to send yet.

Sending only loads the course — the boat does not move until Engage is pressed on the autopilot panel, which is a separate, separately audited action. The vessel validates the plan again itself and refuses with a reason you can read in the command history. Points can also be laid by clicking the chart on the overview page.

Stabilisation

Roll & pitch tuning

Every field is a parameter on the Pixhawk, read and written by the vessel over MAVLink. The column on the right is what the flight controller says it has; the field is what will be sent. Saving is ArduPilot's own set-and-save, so an acked value is in the autopilot's storage and survives a reboot of the Pixhawk, the Pi and this dashboard — which also means a ride-height trim keeps the amas creeping until it is set back to zero. Both trims add to the pilot's knobs rather than overriding them, so the transmitter keeps its authority while this page has its own.
