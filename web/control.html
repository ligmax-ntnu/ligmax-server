Camera feed

Camera state unavailable.

Frames are pushed up from ligmax-json.local as outbound POSTs — on 4G nothing can reach the vessel, so this is the only way a picture gets to shore. The detections and the front lidar do not come this way: they go to ligmax-pi3.local, which merges them with the aft lidar and sends one fused world model up the telemetry link. So a box on the map and the same box in a frame arrive by different routes — do not expect them to line up exactly.

Software

Update from GitHub

The vessel takes its update as a command on the telemetry link, the same way it takes E-stop, and acks the result here. Other nodes poll this server every 30 s from their own update.py; the dashboard updates itself in-process. Every one of them fast-forwards only — a checkout with uncommitted changes refuses the update rather than discarding it. Updating ligmax-pi restarts its nodes, which drops propulsion power for the length of the restart.
